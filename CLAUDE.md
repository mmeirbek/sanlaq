# CLAUDE.md

Инструкции для Claude Code в этом репозитории. Подробности об игре — в `README.md`.

## Проект

САҢЛАҚ — сборник казахских народных игр на **Godot 4.7**, GDScript. Режимы: Соқыртеке,
Абай айтады, Тоғыз құмалақ, Ақ сүйек. Web-сборка деплоится на GitHub Pages.

Документы:
- `docs/REDESIGN_PLAN.md` — текущий план работ по этапам. Главный документ.
- `*_mode_spec.md` в корне — спецификации режимов.
- `SANLAQ_PROJECT_CONTEXT.md` — общий бриф. Разделы 11–12 (визуальный стиль, цвета)
  устарели: действует стиль atilla из плана редизайна.

## Команды

Godot не в PATH: `~/Desktop/Godot_v4/Godot_v4.7.2-stable_win64_console.exe`.

```bash
GODOT=~/Desktop/Godot_v4/Godot_v4.7.2-stable_win64_console.exe

GODOT=$GODOT tools/run_tests.sh                                  # все tools/*_test.gd, как в CI
"$GODOT" --headless --path . --script res://tools/<имя>_test.gd  # один тест
"$GODOT" --headless --import --path .                            # импорт (нужен на чистом клоне)
"$GODOT" --path . --script tools/screenshot_screens.gd -- --size=1560x720   # скриншоты, НЕ headless
```

Размеры для скриншотов: 1280x720 (по умолчанию), 1560x720 (телефон), 960x720 (планшет).

## Тесты

- Тест — `tools/<что>_test.gd`, наследуется от `res://tools/test_case.gd`: `check()`, `finish()`.
- Тест падает и при ошибках движка в логе (`push_error`, `SCRIPT ERROR`), не только при `check()`.
- Классы, которые сами обращаются к автолоадам, в тесте нельзя писать как типы — см. шапку
  `test_case.gd`.
- Правила режима живут отдельно от UI (`scripts/core/game_board.gd`,
  `scripts/core/aq_suyek_match.gd`) и покрыты headless-тестами. Новый режим — так же.

## Как работаем

- Один этап плана — одна ветка `redesign/<этап>-<кратко>` — один PR.
- `main` деплоится на Pages автоматически после зелёных тестов (`.github/workflows/ci.yml`).
  В `main` попадает только проверенное.
- Визуал и механика — разными коммитами. Механика в редизайне не меняется; если нужно —
  сначала тест.
- «Готово» — по разделу «Правила работы» в `docs/REDESIGN_PLAN.md`.
- Сообщения коммитов — по-русски, коротко, как в `git log`.
- Файлы с LF (`.gitattributes`), отступы в GDScript — табы. `*.uid` и `*.import` коммитятся.
- Видимый текст — через `tr()`; строки-ключи по-казахски в `assets/i18n/ui_strings.csv`.

## Как писать код

1. **Сначала подумать.** Допущения называть вслух. Есть два толкования — показать оба, не
   выбирать молча. Непонятно — остановиться и спросить.
2. **Проще.** Минимум кода под задачу. Без фич «на будущее», без абстракций под один случай,
   без обработки невозможных ситуаций.
3. **Точечно.** Менять только то, что требует задача. Соседний код не «улучшать», стиль не
   менять. Чужой мёртвый код — упомянуть, не удалять. Своё неиспользуемое — убрать.
4. **Цель проверяема.** «Починить баг» = тест, который падал и теперь проходит.
   «Рефакторинг» = тесты зелёные до и после. Многошаговая задача — план «шаг → проверка».

## Скиллы проекта (`.claude/skills/`)

| Скилл | Когда |
|---|---|
| `red-green-proof` | Любой баг механики: доказать тестом, который падает без исправления. |
| `grill-me` | Новая спецификация режима или этап плана — до того, как писать код. |
| `adversarial-review` | Перед слиянием PR в `main`. |
| `handoff` | Конец этапа или длинной сессии — документ для следующей сессии. |

Встроенные: `/code-review` — поиск багов в диффе, `/simplify` — чистка после правок.
